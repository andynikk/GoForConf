# Подключение живых данных 1С через GoForConfData.cfe

**Для чтения актуальных данных добавьте `GoForConfData.cfe` как расширение в ту информационную базу 1С, к которой будет обращаться GoForConf.** Расширение добавляет HTTP-сервис `GoForConfData`, через который reader узнаёт конфигурацию базы, описывает источники и выполняет ограниченные запросы на чтение. Так можно проверить фактическое состояние данных и сопоставить его с кодом, найденным в SQLite-снимке.

Демонстрационный ZIP работает со снимком без установки расширения. Для подключения к своей базе запросите отдельный файл `GoForConfData.cfe` у администратора вашей установки GoForConf или у сопровождающего проект. Уточните совместимость файла с вашей версией платформы и конфигурации.

## 1. Установите расширение в 1С

1. Начните с тестовой копии нужной информационной базы. Откройте её в Конфигураторе и выберите **Конфигурация → Расширения конфигурации**.
2. Создайте запись для `GoForConfData` либо выберите существующее расширение при обновлении. В меню окна расширений выберите **Загрузить конфигурацию из файла…** и укажите `GoForConfData.cfe`. [Пример загрузки расширения в Конфигураторе на 1С:ИТС](https://its.1c.ru/db/content/freshnews/src/48749844.html)
3. Проверьте применимость расширения, обновите конфигурацию базы данных для расширения и убедитесь, что оно активно в новом сеансе. В дереве расширения проверьте наличие HTTP-сервиса `GoForConfData` с корневым URL `goforconf-data`.
4. После проверки повторите установку в нужной базе в согласованное с администратором время.

Механизм расширений платформы подключает доработку к основной конфигурации при запуске. [Документация 1С о расширениях](https://v8.1c.ru/platforma/rasshireniya/)

## 2. Опубликуйте HTTP-сервис и выдайте права

1. В Конфигураторе откройте **Администрирование → Публикация на веб-сервере…** и создайте или обновите публикацию нужной базы на IIS или Apache. Включите публикацию HTTP-сервиса расширения `GoForConfData`. Для выборочной публикации администратор веб-сервера может указать этот сервис в `default.vrd`. Используйте HTTPS и ограничьте доступ к публикации хостом reader. [Документация 1С об HTTP-сервисах расширений](https://wonderland.v8.1c.ru/blog/web-i-http-servisy-v-rasshireniyakh/)
2. Создайте отдельного пользователя 1С с доступом к HTTP-сервису и минимальными правами чтения на нужные объекты и данные. Сохраните ограничения на уровне записей, принятые в базе. Для вызовов reader использует HTTP Basic, поэтому веб-публикация должна принимать такой вход. [Реализация шлюза reader](../cmd/goforconf-reader/generated_data_gateway.go)
3. Запишите корень опубликованного сервиса. Для публикации `demo-1c` на `1c.example.org` это `https://1c.example.org/demo-1c/hs/goforconf-data`. Reader сам добавит путь нужной операции, например `/v1/info`. [Пример URL HTTP-сервиса в материалах 1С](https://its.1c.ru/db/content/metod8dev/src/developers/platform/metod/web-services/i8105756.htm)

## 3. Настройте reader и MCP

Reader открывает SQLite-снимок при запуске. Для анализа своей конфигурации укажите снимок этой же конфигурации. Перейдите в каталог с `goforconf-reader.exe` на компьютере, где он будет работать. Запустите команду в интерактивной консоли под той же учётной записью Windows, что и reader.

```powershell
.\goforconf-reader.exe encrypt-data-password
```

Введите пароль пользователя 1С. Ввод скрыт, а результат — строка `dpapi:<Base64>`. Команда выводит строку и оставляет настройки без изменений. Скопируйте её целиком в `oneCDataServicePasswordEnc`. Поле `oneCDataServicePassword` удалите или оставьте пустым. После переноса reader на другой компьютер или под другую учётную запись Windows сгенерируйте строку заново. Держите локальный файл настроек под правами учётной записи reader. [Реализация `encrypt-data-password`](../cmd/goforconf-reader/generated_data_password_windows.go)

Создайте серверный `config.local.json`. Пример ограничивает доступ к reader локальным компьютером.

```json
{
  "databasePath": "C:\\GoForConf\\data\\snapshot.sqlite",
  "httpAddr": "127.0.0.1:8088",
  "httpAccessEnabled": true,
  "httpAccessFile": "C:\\GoForConf\\config\\http_access.clients.json",
  "oneCDataServiceUrl": "https://1c.example.org/demo-1c/hs/goforconf-data",
  "oneCDataServiceUser": "GoForConfReader",
  "oneCDataServicePasswordEnc": "dpapi:ПОДСТАВЬТЕ_РЕЗУЛЬТАТ_КОМАНДЫ"
}
```

Для указанного пути создайте файл политики HTTP. Замените пути, имя публикации и пользователя в серверных настройках на свои.

```json
{
  "version": 1,
  "clients": [{"name": "local-mcp", "ip": "127.0.0.1", "enabled": true}]
}
```

Запустите reader с этими настройками. Если на порту `8088` запущен демонстрационный reader, сначала остановите его.

```powershell
.\goforconf-reader.exe --config .\config.local.json serve
```

В отдельном клиентском `client.json` задайте адрес reader и путь `mcpForbiddenFieldsPath` к файлу политики полей. Относительный путь к политике считается от каталога `client.json`. Укажите абсолютный путь к `client.json` в переменной `GOFORCONF_CONFIG` у процесса MCP-адаптера. URL публикации 1С и пароль хранятся в серверных настройках reader. [Пример настройки MCP-клиента](../examples/mcp-client/README.md) · [Политика полей](../config/mcp_forbidden_fields.md)

## 4. Проверьте подключение через MCP

1. Вызовите `health` с `{}`, чтобы проверить доступность reader.
2. Вызовите `get_data_service_info` с `{}`. Для совместимого шлюза ожидается `protocolVersion: 1`. Сверьте имя и версию конфигурации в `configuration` с ожидаемыми. Результат `health` не проверяет публикацию 1С.
3. Вызовите `describe_data_source` с `{"source":"Справочник.Номенклатура"}`, если в тестовой базе есть этот справочник. Для другой конфигурации подставьте существующий разрешённый источник. Сверьте имена полей с полученным описанием.
4. Вызовите `execute_data_query` с явными полями и малым лимитом. Этот пример читает до пяти строк из справочника тестовой базы.

   ```json
   {
     "source": "Справочник.Номенклатура",
     "select": ["Код", "Наименование"],
     "limit": 5
   }
   ```

В ответе `columns` задаёт порядок колонок, а `rows` содержит значения в этом порядке. `truncated: true` означает, что результат ограничен. Для текстового языка запросов есть `execute_data_query_text`. Используйте один `ВЫБРАТЬ` с явными полями, параметрами и узким фильтром. `maxRows` ограничивает объём ответа, а `ПЕРВЫЕ N` задаёт лимит строк в самом запросе. Для снижения нагрузки сужайте выборку условиями. `investigate_with_data` дополняет расследование кода переданными ему узкими проверками на живых данных.

Политика MCP проверяет запросы `execute_data_query` и `execute_data_query_text` и имена колонок в их ответах. Используйте явные списки вместо `*`. Контекстные поля допускаются только для явно разрешённых источников. При `data_access_denied` сократите запрос до разрешённых полей или согласуйте доступ с администратором. HTTP-шлюз reader пересылает запросы в 1С, поэтому права пользователя 1С и ограничение сетевого доступа обязательны независимо от политики MCP. [Проверка полей в адаптере](../cmd/goforconf-mcp/forbidden_fields.go)

## Диагностика

| Признак | Что проверить |
| --- | --- |
| `health` не отвечает | Убедитесь, что reader запущен, `client.json` указывает на его узел и порт, а IP адаптера разрешён в политике reader. |
| `503`, `1C data service is not configured` | Проверьте `oneCDataServiceUrl` в конфиге, с которым запущен reader. Перезапустите reader после правки. |
| `401` или ошибка авторизации | Проверьте пользователя 1С, пароль и поддержку Basic в веб-публикации. |
| `403` | Проверьте, на каком участке получен отказ. Reader ограничивает IP по своей политике, а веб-публикация и 1С проверяют права отдельно. |
| `404` от публикации 1С | Проверьте имя публикации, загрузку и активность расширения, публикацию HTTP-сервиса и корень URL без `/v1/info`. |
| `502` или таймаут | Проверьте доступность веб-публикации с компьютера reader, DNS и сертификат HTTPS. Для большого ответа сократите запрос. |
| `decrypt oneCDataServicePasswordEnc` | Проверьте формат `dpapi:` и сгенерируйте строку под Windows-учётной записью reader. |
| `schema_describe_failed` или `query_rejected` | Проверьте, что объект и поля существуют в этой конфигурации и пользователь вправе читать их. |
| `data_access_denied` | Уточните исходное поле и источник по политике MCP. Выполните проверку снова через MCP с разрешёнными полями. |
